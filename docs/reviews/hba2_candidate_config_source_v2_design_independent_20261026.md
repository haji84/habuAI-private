The proposed separate module keeps the source-v1 function bodies, old config acceptance, callbacks and callers unchanged. Explicit source-v2/cfgv3 selection prevents silent legacy upgrades. The complete fixed triplet and native recipe schemas come from the preparation validator, while the new physical reader binds both implementation maps and both A2 requirements to actual bytes. A digest of another declaration alone cannot satisfy that binding. The design makes physical JSON hashes and canonical parsed hashes distinct.

The first-read and first-rescan phase retains one caller-owned context, its absolute deadline and prior actual charges. The 16MiB phase bound is additional to the existing global allowance and does not refill or restrict/reset the context. The original-ref rescan and complete membership checks are supported by the existing reader/recheck interfaces. Later rechecks remain separately charged and cannot rewrite an earlier sealed receipt. Contradictions are validated before a consistent late declaration is classified as SourceBlocked.

No broad exception classifier or fitting API is needed. Original callback identity is an explicit implementation acceptance condition, including BaseException and final hashing; actual guarded helper tests must prove it. If an existing helper wraps an original exception and repair requires old-file edits, implementation must report that separate dependency rather than expand its scope. No such runtime proof is claimed by this review.

Residual risk is MEDIUM: the new module must faithfully own refs before caller callbacks, validate the actual context limits and nonnegative cumulative ledger, bound both declared and actual phase bytes, preserve strict readiness maxima, and detect changes during actual rescans. Cooperative validation does not establish an atomic hostile-filesystem snapshot, loaded-bytecode authentication, installed numerical dependencies, issuer identity or historical prereveal availability. The specification states these limits and leaves every authority flag false.

Implementation remains gated on the preparation pipeline's own genuine pinned-backend test, exact-head CI, verified main integration and fresh-main CI, followed by an explicit ROOT dispatch against the then-verified bytes. At this review, that new preparation CI is still pending. The historical preparation source `8654a1c` and independent acceptance are not substitutes. The implementer must refresh those pins and collect the specified old whole-output/read-order/callback/REPLAY baselines before editing; an old incomplete code closure is expected to fail membership after a new module is added.

Required implementation evidence includes independently rehashed bad recipe/requirement maps, known-invalid plus late declarations, exact boundary equality, every file and phase cap, genuine nonzero prior charges and exhaustion, forbidden namespaces and static links before opens, original callback objects at real read/config/final-seal seams, full ordered consumed refs, actual later rescan changes, owned sealed outputs, and unchanged old-source artifacts under identical declarations. Existing goldens must not be regenerated from new code. Numerical fit, source registration, summary/Stage1/parent/registry A2 integration and scientific acceptance remain outside this slice.
