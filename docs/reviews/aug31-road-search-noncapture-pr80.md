# PR #80 実GPX × 道路照合 × 非捕獲候補 2026-08-31

## 目的と境界

2026年8月31日探索夜の実際のGPXを、既存のハブログと既存OSM道路中心線に照合し、GPSの道路近接・速度・探索記録を根拠としたレビュー対象を生成する。

「探索らしい速度で道路を通過」と「実際にハブを探した」は異なる命題。独立の探索証拠が欠けている現状では**正式に認証した探索道路区間=0、学習用Negative=0、学習用Positive=0**。速度やGPS通過だけから不在を断言しない。

## 既存原本の使用

- 元GPXは `data/raw/gpx/2026-08-31__legacy.gpx`。SHA-256と点数17,906、朝07:00探索夜境界を `evidence/legacy/habuAI-public/v2_actual_gpx_13night_qc.csv` と照合。
- 原本の抽出文書 `evidence/recovered_sources/2026-08-habu-log-10506-lines-library-read.txt` を使用。これはLibraryからの抽出テキストで、元TXTのバイトが独立認証されたわけではない。
- ハブログで探索開始20:29、終了は翌01:29。捕獲記述は21:43と翌01:17の2件。両件GPX時空間近接を既存監査関数で検証。
- OSM原本は `artifacts/Habu_AI_OSM_Road_Grid_2026-09-25.zip.parts/` の33分割の既存ZIP。既存の `scripts/verify_osm_road_archive.py` によりZIPのSHA・CRC・安全なパスを確認。中心線GeoJSONLのSHAを別途照合。
- このOSMは9月25日アーカイブであるため、8月31日の予測前に参照可能だった公式道路母集団と扱わない。**事後診断用補助道路地図**。

## 処理

1. OSMの利用可能候補道路の各直線セグメントをUTM52Nへ変換し、近傍照合用の100mグリッドに索引化。GPS点から線分への最短距離が35m以内なら暫定一致候補。複数道路に8m以内の距離差で一致する場合は交差・並走の曖昧判定。道路は地理データから新造せず、GPS点間も架空の経路で補間しない。
2. GPXの異常点、HDOPが10超の点を除外。HDOP欠損は品質不確実として残すが、検索類推の根拠サンプルには数えない。速度はGPX記載のm/s値を優先し、欠損なら連続する5秒以内の二点のみの測位直線距離による速度目安を計算する。推定速度は**行動の証明ではない**。
3. 07:00境界とハブログ開始・終了を照合し、100m×10分のサンプル区間へ統合。8月31日の過去GPX監査は688単位。複数サンプルの低速走行（0.5〜6m/s）、高速走行（11m/s以上）、停止、道路近接曖昧をレビュー候補として分類。頻度・時間の条件を満たさないものは UNKNOWN のまま。
4. 捕獲記述・ハブ目撃の近傍時空間を別分類し、非捕獲候補から除外。低速・道路一致などが成立し捕獲記述が近くにないセルだけ `NO_OWNER_CAPTURE_RECORDED_REVIEW` を生成する。これは「記録に捕獲記載なし」という意味であり、実際に捕獲できなかったことの証明ではない。
5. 詳細なセル座標・道路IDはGitHub Actionsの**プライベートアーティファクト（7日保管）**のみ。PRドキュメントや公開ダッシュボードに捕獲地点詳細は追加しない。

## 合格条件

- 原本SHA・実GPX 17,906点・2捕獲記述GPX一致・本人確定月計47匹・累計243匹に変更を加えない。
- 688個のGPS観測セルをすべて1回だけ分類し、分類数が688に一致する。
- 実OSM中心線ZIP・GeoJSONLソースSHAが妥当で、道路近接が有意に検出される。
- 速度・交差道路・未測位・開始終了の不備によって学習用0ラベルが生まれないことをテスト。
- 元データ・元予測・本人月計は保持し、UNKNOWNを学習用Negativeに勝手に変更しない。
- 本人による区間単位の探索有無の検証と、当夜の捕獲結果網羅性・正式個体IDの独立照合は次の審査に残す。これらがない段階で「実探索道路の認証完了」と宣言しない。
