# Proposed Task 8 boundary for reviewed source and private operational state

Status: **proposal for owner review**. It grants no access or write authority and does not change the existing production gates. See [the Task 8 design](master-goal-1642-production-trust.md) and [the registry state core plan](production-registry-state-core-20261104.md).

The development repository is public. Its verified PR, code, CI and review facts establish the identity of the program that may run. They cannot authorize putting model artifacts, forecasts, tracks or owner logs into that repository. At PR #159's reviewed starting head, the controller also requires the registry policy repository to be identical to the source repository. With a synthetic predecessor, keeping those identities equal allows only an unpublished proposal; substituting a different state repository fails with `ISSUANCE_REPOSITORY_MISMATCH`. Removing that check alone would let an input choose the destination.

Keep the source repository fixed. Add a versioned binding to a separate, owner-approved, existing private state repository and one designated state ref. The reviewed policy binds both immutable repository IDs, their roles, the source branch and code closure, and the state ref and existing validated anchor. The public review can commit a digest of the exact private policy without publishing its location or contents. The active fixed coordinator obtains both repository facts through the approved authenticated transport and matches them to that policy. It rejects unknown visibility, a public or internal state repository, an ID or ref mismatch, changed permissions or an unapproved anchor. A saved caller receipt, a fixture or a public PR cannot substitute for those observations. The sealed independent evaluation store remains outside both operational roles.

Use the existing state-machine operations and immutable record formats where compatible. Explicitly version the boundary rather than reinterpreting old single-repository records. Authenticate PRs, reviews, CI and compatible code against the source identity. Authenticate the pointer, parent commits, private bytes, publication acknowledgements and immutable versions against the state identity. Include the policy binding in the private operation identity and preserve it across retries. Keep the current development and diagnostic paths read-only. Without an approved binding, complete state or a supported private transport, return a blocker before publishing.

For writes after separate operational authorization, the active coordinator checks the private destination and exact predecessor again, builds one commit with that sole parent, and performs the supported non-force expected-ref update. A visibility read and a ref update are separate operations. Before permitting writes, verify that the approved destination controls keep it private throughout the write or that the transport enforces this property. Block when that invariant cannot be established. Promotion and issuance share the same ref. On timeout, reconcile the exact proposed commit and bytes against validated current history; a competing child is a conflict and an incomplete read remains unknown. A missing predecessor requires a separately reviewed bootstrap; ordinary branch creation and a public copy are not substitutes.

Check the actual prospective clock again before publication. For formal scoring require authenticated read-back of the exact committed version and all referenced artifact bytes before the earliest of planned start, the first forecast window, and actual exploration start (once established), or equivalent approved service proof that all those bytes were durable before that limit. Git author/commit dates, declared freeze times, request start and late acknowledgements alone do not establish timely durability.

Acceptance should first use temporary Git repositories and a synthetic transport. Exercise swapped identities, caller-chosen destinations, visibility changes, stale source reviews, wrong state anchor, concurrent different children, lost acknowledgement, repeated version, a P0 stored before departure but after the first forecast window, and late or missing referenced bytes. Prove that no writer call occurs for unapproved or public destinations and that public output contains no raw bytes, coordinates, model weights, private IDs or references. Then verify the approved real private destination read-only before proposing any real write. Passing synthetic tests cannot stand in for qualified learning data, a prospective P0, a real return with original evidence, or an independently eligible Champion.

Owner decisions needed: approve this separation and identify an already approved private operational repository/ref (or approve a specific separate bootstrap after review). Actual field validation also needs the next search start before departure and source-bound return evidence. Main integration and production activation retain their separate approval requirements.
