# PDCA Single-Entry Orchestration Specification v1.0

Status: Normative design
Depends on: prediction-freeze-versioning.md

## Goal

The PDCA surface is the single operational entrypoint after an exploration session. A user instruction equivalent to "run today's PDCA" starts one bounded pipeline. Prediction generation remains a separate surface and is never silently regenerated by PDCA.

## Pipeline

1. Resolve operational night using Asia/Tokyo with the 07:00 boundary.
2. Load every frozen ORIGINAL prediction for that night: P0, then P1...Pn.
3. Verify immutable payload integrity and SHA-256 metadata.
4. Load available actual evidence: GPX/search trace, capture DB, reaction DB, weather/road observations and approved auxiliary inputs.
5. Audit evidence quality. Never manufacture missing evidence.
6. Build observed exposure units. Absence of capture becomes Negative only where actual search/passage is evidenced in the matching 100m x 10-minute unit.
7. Score P0 using only outcomes after P0 cutoff_time.
8. Score each P1...Pn independently using only outcomes after that version's cutoff_time.
9. Report pre-exploration performance separately from real-time adaptive performance.
10. Run error decomposition by area, road zone, time window, conditions and available feature groups.
11. Run leakage-safe model evaluation/walk-forward using only information available before each historical cutoff.
12. Generate feature/model hypotheses. Hypotheses are not accepted improvements.
13. Validate candidate improvements with walk-forward and ablation where applicable.
14. Produce an Act decision:
    - ACCEPT_CANDIDATE: evidence supports promotion for future prediction testing;
    - REJECT_CANDIDATE: evidence does not support it;
    - NEED_MORE_DATA: evidence is insufficient.
15. Store the PDCA report, evidence references, metrics, model/version references and reproducibility metadata.
16. Never rewrite ORIGINAL prediction history. Any retrospective model run is REPLAY.

## Single-entry command contract

The entrypoint accepts:
- operational_night: optional; defaults to the latest resolvable exploration night;
- mode: full by default;
- prediction_scope: ORIGINAL by default;
- allow_replay: false by default.

The entrypoint must stop or downgrade affected stages when required evidence is missing. It must not fill gaps by assumption.

## Stage status

Every stage returns one of:
- PASS
- PARTIAL
- BLOCKED
- FAIL

PARTIAL/BLOCKED must include the missing dependency and must not be presented as completed analysis.

## Separation from prediction generation

PDCA may read frozen predictions but must not create or alter P0/P1/P2... ORIGINAL predictions.

The prediction surface owns prediction issuance and Freeze.
The PDCA surface owns post-observation scoring, diagnosis, validation and improvement evidence.

This separation is mandatory to prevent hindsight leakage.

## Outputs

Canonical outputs should include:
- run_manifest.json
- evidence_manifest.json
- prediction_integrity_report.json
- exposure_100m_10min dataset/reference
- p0_score.json
- realtime_scores.json
- error_analysis.json
- walk_forward_report.json
- ablation_report.json when applicable
- act_decision.json
- pdca_report.md

Every output records the source prediction IDs/cutoffs and relevant data/model hashes.

## Automation boundary

"Single entrypoint" means the pipeline can coordinate all PDCA stages from one request. It does not mean unavailable data, missing executors, or unimplemented model stages are magically completed.

Until every stage has an executable implementation, the orchestrator must truthfully mark that stage BLOCKED rather than simulate success.
