# HUB NATURAL / 小型CPUレビューAI 品質優先ゲート（PR #136）

## 判断（2026-11-02）

**新機能・対応領域の拡張を一時停止して、既存Qwen審査の信頼性を優先する。** 新しいコード生成機能、他サービスへの自動連携、新たなモデル追加を先行させない。

対象は既存PR #136。外部CodeRabbit/Copilotレビューは品質ゲートに使わない。ユーザーが明示した独立AI方針に従う。

### 出発点と問題の切り分け

- モデル: `qwen2.5-coder:1.5b`、実行: GitHub-hosted CPU上のlocalhost Ollama。モデルがsource diffを80/80区間処理しても、品質合格ではない。
- 前回のrun `41315050313` は80区間/22ソースの入力を全処理し、211個の**未検証**指摘候補を生成。
- 211件の一次静的照合は「明確な矛盾154、バグとして成立しない53、追加検証4」。これは全211件の再現試験やモデル精度推定ではない。モデル修正後との比較は入力・採点母数を固定してから行う。
- 典型的な誤り: 差分にない関数・閉じタグを「未定義」「欠落」と推定、同じ先頭12/13/14行への架空の参照。審査プロンプトに行番号12の例があったため、行の偏りに影響した**可能性**がある（因果未証明）。
- **コードの引用に成功したことは、指摘の正しさではない。** 実際の入力・再現テスト・独立照合を必要とする。

## 品質ゲート（機械的に実装した初段）

1. 出力例から固定の行番号を除去する。変更行の**実際の新ファイル行番号**と、その行にある連続した原文 `code_quote` を要求する。
2. GitHub上の固定HEADと完全diffを用い、行番号・追加行・正確な文字列引用を照合。欠けた/捏造した行は指摘候補として通さず、**件数と拒否理由は残す**。
3. 実モデル推論で**既知の欠陥2件＋正常コード4件**の小型キャリブレーションを毎回行う。欠陥2件は引用と問題の対応を確認し、正常4件に1件でも指摘があれば `HOLD`。この6例は「起動健全性検査」であり、精度認定ではない。
4. 元差分の全区間処理、キャッシュのmodel digest・プロンプト・審査プログラムrevisionへの紐づけ、原本位置情報の非公開、安全な失敗停止を引き続き検証する。
5. モデル生成候補は `raw` / `location_anchored` / `rejected` と区別。位置が合うだけでバグ確定・PR承認とはしない。

## 正式な「品質が改善した」の判定条件（未達）

- 第1段階：合成キャリブレーション6/6成功、アンカー偽装を0件通過、レビュー契約テストと通常CI合格。
- 第2段階：**独立に正解を付けた最低40例（既知不具合20件以上＋正常20件以上）**を、機能・言語・差分長さ・境界条件で分散して事前凍結する。判定前にモデルへ回答ラベルを提供しない。件数不足なら `INSUFFICIENT_EVALUATION`。
- 第3段階：実モデルの候補を一対一で再現して算出する。参考目標は**precision 95%以上、recall 80%以上、正常ケースでの虚偽警告率5%以下**。重大なデータ欠損/位置公開の既知欠陥の取りこぼし0件。これらは**目標値**であって実績ではない。
- 第4段階：実行をまたぐ再現性、モデルdigest固定、証拠の独立チェック、GitHub Actionsの成功、端末実機（保存→圏外→ロック→再起動→復元）は**別ゲート**で合格を確認。Qwenと別のローカルAIによる検証も、モデル実行/独立性の証拠がある場合のみ有効。
- 同一問題の重複、候補の欠測/引用不能、再現不能例を「0件の不具合」扱いにしない。疑問は `INCONCLUSIVE` に置き、必要なら正解ラベルを追加する。

## 継続禁止とHuman Gate

- この品質ゲート未達で新機能を増やしたり、mainへ統合・本番公開することは禁止。
- 公開リポジトリに生GPS、捕獲地点、本人の原文ログ、認証情報を新規投入しない。AI外部サービスへの送信と追加課金・認証/権限変更は行わない。
- GitHub Actions `success` は入力処理/コードテストの結果であり、GitHubの公式レビュー承認やユーザーの端末実機受入に代わらない。

## 固定40例の実測ベースライン（2026-11-02、評価問題は変更禁止）

- 凍結原本: `tools/dashboard_ai_review/holdout_v1.py`、Git blob `daac52dfed89cb946e736aed49ed109a56307ffa`、SHA256 `6a679c26f775970a2d55e53e8d3870c6c9cbd8320c530b77725de83af7e8fc8a`。既知欠陥版20・対になる正常版20、Python 24件・JavaScript 16件。合成データのみ。
- 比較対象のQwen digest: `d7372fd828518a4d38b1eb196c673c31a85f2ed302b3d1e406c4c2d1b64a0668`。
- 実測A [run 41355358801](https://github.com/haji84/habuAI-private/actions/runs/41355358801)、実測B [run 41359553081](https://github.com/haji84/habuAI-private/actions/runs/41359553081) はともに40/40回答、各ケース1件の指摘、指摘なし回答0件、解析失敗0件、実コード行との引用照合が成立したのは8件、拒否32件。
- Bの引用拒否内訳: `INVALID_QUOTE=17`、`QUOTED_TEXT_NOT_ON_SOURCE_LINE=15`。Python 24ケースは引用一致0件。JavaScript 16ケースでは一致8件。このうち不具合版の実装行を指した**候補**は3件。内容として実際のバグを正しく説明できたかは未検証。
- ラベル上の正常20例に20件の警告（100%）。これは**固定仕様・単一実行証人に対して正常とラベル付けした例に警告した割合**であり、指摘本文20件すべてを独立に反証した実製品FPRではない。見かけ上の正常ラベルを過信せず、重大な指摘は個別の再現試験で真偽を判定する。
- Bの`proxy_precision_ceiling=0.375`は「引用位置に一致した8件」のうち標的の不具合行を示した3件という、**内容未検証のproxy**。Aの`0.1304`と異なる分母なので、0.1304→0.375を性能改善として比較してはならない。proxy再計算・診断項目追加はモデル性能の向上ではない。
- 審査の現在判定: `HOLD`。モデルの誤指摘をGitHub正式承認/確定バグ/コード修正指示へ自動昇格させない。

### 固定ラベルのまま実施する品質改善

1. `measure_holdout.py`にPython/JS別の欠陥・正常母数、誤警告候補、引用一致、拒否理由、棄権の集計を追加。`test_holdout_scoring.py`で、全例に警告するAIがHOLDになること、正常20例が都合よく除外されないことを回帰試験する。ケース、ラベル、合格基準は変更しない。
2. Qwenの個別の指摘本文を、合成ケースに限定して安全に検証し、コード上の反例で確認できたものだけを正式な不具合候補とする。推測やスタイル改善は不具合に含めない。
3. 自前のローカル小型AIで意味上の検証が再現できない限り、審査結果は`INCONCLUSIVE`または`HOLD`。ゼロ指摘で見落としを隠したり、誤指摘があるケースだけを評価から削除したりしない。
4. 今後モデル/プロンプトを変更する場合も、固定原本と判定母数を変えず、前後の両指標を再測定する。既に結果を見たこのv1評価群への適合は最終的な未見ケース性能を保証しないため、別途未見データでの検証が必要。
